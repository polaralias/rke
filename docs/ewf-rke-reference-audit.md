# EWF / RKE reference separation audit

Packages: [EWF methodology](../skills/engineering-workflow/SKILL.md) and [RKE runtime adapter](../.agents/skills/rke/SKILL.md).

Reviewed all 27 resources in EWF 5.35.2's pre-rewrite `references/` tree, including the schema, navigation map and files with no command hits. The baseline was captured before rewriting; this inventory describes that baseline, not the new method references. The separation preserves engineering judgement in EWF and moves deterministic mechanics to `.agents/skills/rke`. RKE is an adapter, not a second methodology.

The scan covered full `rke` invocations and abbreviated operation words (`context`, `structure`, `knowledge`, `documentation`, `coordination`, `handoff`, `task`, `tracker`, `host`, `journey`, `capability`, `gate`, `closure`) with operation verbs. Every file was also reviewed for useful guidance that a command-only search would miss. “Hit lines” below counts lines mentioning `rke` or a recognized abbreviated operation, not commands or capabilities; a zero does not imply the file was skipped.

Targets prefixed `EWF:` are under `skills/engineering-workflow/references/`; `RKE:` targets are under `.agents/skills/rke/references/`.

This is a source/reference audit and package separation record; it does not claim executed agent evaluation, live-host adoption, publication or release qualification.

## Pre-existing working-tree changes

The baseline included the uncommitted EWF 5.35.2 navigation, reference-map, editorial and compatibility changes. It was captured from the working tree rather than reconstructed from HEAD. The initial RKE implementation tree had no `src/` changes. Pending qualification/coverage scripts introduced source-clause identity, destination and reachability checks; these are structural evidence and do not qualify an agent's engineering decisions. The adapter retains that distinction and the pending runtime documentation corrections, including source-change transaction guards, current operation coverage, reader boundaries and source/package evidence limits.

The separate OKF Tasks checkout was inspected read-only. Its 144 modified tracked files had no semantic diff after ignoring end-of-line differences. No normative schema or tool change was identified from that dirty tree. The catalogue's pending RTL update for exact producer bytes and extracted-package validation was preserved. Historical RKE/QTK/DDD routing in that wrapper now explicitly names EWF's knowledge, clarification and design methods, keeping the newly separate runtime adapter from becoming the author of canonical truth.

New skill artifacts do not inherit the prior candidate's release or hosted-agent qualification. Prior source identities and review receipts remain visibly stale. Registration now includes the new adapter sources so later adapter changes participate in knowledge-impact review. The new packages are independently versioned and their catalogue provenance remains `unreleased`.
