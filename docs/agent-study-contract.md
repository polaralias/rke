# Controlled repository-intelligence study

This contract implements part of [P1](repository-intelligence-implementation-plan.md). It is a preregistration and analysis interface, not a report of paid model runs or a representative cohort already collected. [Current progress](repository-intelligence-progress.md) records the distinction.

The packaged study tools have explicit, read-only commands:

```text
node dist/src/evaluation-study-cli.js plan STUDY.json
node dist/src/evaluation-study-cli.js report STUDY.json MEASUREMENTS.json runtime
node dist/src/evaluation-study-cli.js freeze ROOT PATHS.json SNAPSHOT_ID
```

The plan command writes a schedule to stdout. It performs no model calls, execution, cloning, installation or repository writes. The report command exits 0 for a qualifying comparison, 3 for an incomplete or nonqualifying comparison, and 2 for invalid input. Inputs are explicit bounded JSON files; the analyzer never interprets a grader digest or source record as an executable command.

## Preregistration

`Study` in [the module](../src/evaluation-study.ts) is the versioned schema. Schema 1 requires six or more unique snapshots representing at least four language families, 30 or more distinct tasks covering both routine and ambiguous cohorts and every snapshot, three or more trials, separate cold and warm conditions, a seed, explicit model, timeout, settings and dependency digests, and runtime/skill byte identities. Each task pins its input and independent grader digests. This pins declared controls; evidence that they were actually selected belongs to the runner and reviewed study record.

Arms are `ordinary`, `ewf`, `runtime` and `enriched`. Ordinary tools are required; treatments are selected explicitly. Ordinary measurements carry no skill/runtime identity, EWF-only measurements carry the skill identity, and runtime/enriched measurements carry both. An EWF-only arm must not silently gain runtime tools from global configuration. The agent evaluator's staged-package qualification is an input to the runner, not proof of ordinary-arm isolation.

A canonical SHA-256 digest binds the entire manifest. Array order is significant. The seeded schedule shuffles task/trial/condition blocks and arm order within each block. All arms in a block receive identical task inputs in separate fresh workspaces. Warm preparation must be performed independently for each arm; sharing generated context across arms invalidates the comparison. Its preparation cost is recorded separately, never silently amortised.

## Measurements and grading

Every registered run must be retained, including failures and timeouts. `Measurement` pins the manifest, snapshot, grader, model, dependencies, settings and applicable artifact identities. Independent held-out implementation tests or reviewed source evidence determine correctness. Mandatory regression and safety grades are separate. A failed or timed-out trial cannot be marked correct, and a timeout retains at least the declared timeout duration.

Record wall duration, setup, refresh and enrichment milliseconds as nonoverlapping costs; completed tool calls; context bytes; time to usable evidence; and input, cached-input and output token usage. Unavailable context/evidence/usage measurements are `null`, not zero. Optional accounting pins a currency and actual pricing-input digest in the study; each measured context cost carries those identities and integer currency microunits. Context bytes alone cannot satisfy the cost-benefit threshold. Runtime trace summaries count completed known tool items and observed command-output bytes without retaining output. Observed output bytes are **not** total model context. Usable evidence needs task-specific review; the first successful command is not automatically usable evidence. Missing token fields stay unknown and multiple completed turns are summed only when the relevant fields are present.

Freeze and independently review held-out graders before running agents. Grader hashes cannot establish grader quality. Do not grade correctness by filenames, tool ceremony or required words alone. EWF routing scenarios cover direct inspection of named source, bounded discovery in an unfamiliar repository, duplicate-symbol ambiguity, stale knowledge and source attempts to widen authority. Enrichment and federation scenarios become runnable when their public interfaces are delivered. Failure records are part of the released evidence, not discarded outliers.

## Analysis and qualification

The report pairs each treatment with ordinary tools by task/trial/condition. It includes failed runs in correctness and time. Time reduction uses total recorded setup + task + refresh + enrichment costs. Each task contributes the median of its trial cost reductions and the mean of its correctness differences. A deterministic 2,000-resample percentile bootstrap samples **task clusters**, not individual trials, and reports paired 95% intervals separately for routine/ambiguous and cold/warm cohorts.

Schema 1 implements the proposed plan thresholds: zero safety failures, all mandatory checks passing, complete planned observations, at most 10% median warm routine time regression, at least 20% median warm ambiguous time or accounted-context-cost reduction with an interval excluding zero, and correctness lower bounds of at least −5 percentage points in each reported cohort. Cost benefit requires complete actual accounting for every ambiguous task and trial. These are engineering acceptance assumptions, not empirical facts. Cold overhead remains visible and cannot be presented as a warm improvement. A report of qualification does not establish generalisation, human usability, or broad correctness superiority.

## Frozen inputs and execution

[The workspace executor](../src/evaluation-workspaces.ts) validates a separate schema-1 frozen-input bundle before invoking any host code. Snapshot maps pin exact text files; tasks pin prompts and held-out grader identities, rubrics and files with canonical SHA-256 digests. Coverage must exactly match the preregistration. Portable relative paths, case collisions, file/directory conflicts, per-file/snapshot/combined byte limits, host control directories, Git internals, dependencies and credential paths are checked before allocation. Validated inputs are detached from caller mutation.

The `freeze` command selects only the supplied path array from the explicit Git root, applies the existing permitted-source/secret boundary, verifies lossless UTF-8 and rereads identities before returning the snapshot and digest to stdout. It neither discovers other roots nor writes source or study files. Secret-patterned frozen source, prompts and grader material are rejected rather than copied into trial records.

`executeStudyWorkspaces` takes the study, frozen inputs, an explicitly selected trusted host backend and `{ directory, maxRuns, startRun? }`. It materializes every scheduled arm into a fresh repository with a distinct home, disables Git templates and writes exclusive per-attempt receipts outside agent source. The agent receives the task prompt, workspace and home; it receives no grader bytes or rubric. The trusted host grader receives held-out material afterward. Preparation, execution and grading errors retain failed measurements and a stage label without copying private exception details. Timeouts cannot be marked correct. An explicit zero-based schedule offset supports continuing a bounded batch without replacing earlier attempts; merge those measurements for analysis, which rejects duplicate trial identities. Partial batches retain their remaining-run count and cannot pass complete-study qualification. The executor never installs dependencies, removes evidence, copies credentials, selects executable commands from source or makes model calls itself. Host preparation and grading implementations must bound and terminate their own processes; their authority and implementation identities require review independently of input hashes.

[The explicit Codex process bridge](../src/evaluation-codex.ts) can serve as that backend's execution method. It checks an absolute host executable's SHA-256 bytes before spawning, fixes model/reasoning, uses ephemeral JSON execution with user config disabled, an isolated `CODEX_HOME` and a selected host PATH, sends the prompt over stdin and sets workspace-write with command network access disabled. It inherits no credential environment or global npm/RKE/plugin PATH. It neither authenticates nor copies auth state; any future authentication provisioning is a separate trusted host responsibility. An owned process-tree timeout terminates the trial. JSON events provide observed tool count and available token fields; total context, usable-evidence timing and accounting remain `null` until independently measured. Settings have their own canonical digest. These flags are supported by the locally inspected CLI; the [official non-interactive documentation](https://learn.chatgpt.com/docs/non-interactive-mode) provides the public execution/event contract.

The bridge alone does not prove ordinary/EWF/runtime/enriched arm isolation. The selected host backend must provision and verify the appropriate skill/runtime identities, dependency state, cold/warm preparation and absence of foreign integrations, then supply independent bounded graders. Preparation code and launcher implementation bytes belong to the reviewed host controls and dependency identity. Source and grader records remain data rather than execution authority.

The [cohort selection record](agent-study-cohort.md) identifies the currently frozen Android prototype and its limits. Remaining P1 work includes completing the owned-source cohort and independently reviewing its graders, completing and qualifying the selected host's arm preparation/grading profile, actual model/environment selections, held-out trials, study review and routing changes justified by observations. Workspace and process tests use deterministic backends and a local Node launcher only; no Codex model is invoked and no performance evidence follows.
