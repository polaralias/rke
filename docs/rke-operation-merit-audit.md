The 43 CLI/MCP operations share one registry. MCP descriptions now state intended use, returned evidence and key limits; tool-choice quality remains an empirical question. The SQLite database remains a disposable projection for incremental retrieval and structural evidence. The [real-repository measurements and paired agent cases](cross-language-evidence.md) show that search ranking can rescue a relevant file from many `rg` candidates, but a small obvious extension costs the EWF/RKE route roughly twice the time and tokens without a correctness gain. The Python case also shows retrieval can miss the first ten unscoped results. Therefore `context find` remains a conditional navigation aid, and the EWF route now stops after a local delivery slice unless closure is requested. No new retrieval command or ranking table is justified.

The [claim-binding prototype](claim-binding-prototype.md) reuses `documentation assess` rather than adding another public operation or SQLite table. Selected tracked bindings improved the precision of review candidates in the four required cases. Their whole-file digest maintenance cost rules out making them universal. `structure map`, benchmarks, host installers, and handoff variants remain specialist routes. The static `legacy route` lookup, machine explanation receipt, and small-change shortcut were removed: their value was prose routing or validation of agent-authored text, and they added closure cost without stronger evidence. Reassess other specialist operations with agent task evidence rather than operation count alone.
