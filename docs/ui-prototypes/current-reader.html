Repository intelligence

ArchitectureAuthored knowledgeReview required

A repository is easier to work in when its evidence, decisions and delivery stay connected.

RKE brings those surfaces into one workspace. A task can point to the design that explains it, the source that implements it and the checks that make its outcome reviewable.

Compare with the previous wording

A shared index establishes that documentation is current.

A shared index helps find documentation. Current source evidence and deliberate review establish whether its claims still hold.

Three boundaries, one workspace

Knowledge describes the accepted shape of the system. Source and executed checks establish observed behavior. Task records describe the work still needed to bring them into agreement.

A useful distinction

Finding a document does not verify it. A fresh index means the search surface is current; it does not mean every statement is true.

  • Knowledge: intentionally authored decisions, architecture and operating context.
  • Evidence: source, test results and explicitly labelled generated explanations.
  • Execution: task status, workstreams, effort and remaining obligations.

From knowledge to delivery

Start with the outcome and inspect the implementation that owns it. Keep the task connected to the relevant knowledge, then record validation against the actual change.

Understand→Change→Verify→Align
rke context find "task lifecycle" --root .
rke task get --task unify-views --root .
rke context impact --changed src/reader.ts --root .

Verification needs a clear claim

A passing schema check establishes structural validity. An executed browser flow establishes the behavior exercised by that flow. Neither should silently become a claim that every user journey is correct.

Keep the limit of each result visible. Review the exact source and the relevant documentation together before describing the work as complete.
