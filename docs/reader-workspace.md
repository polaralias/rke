# Repository reader workspace

The optional actual-browser contract is `node tests/reader-browser.contract.mjs <absolute-browser-executable> <packed-workspace-reader.html> [mobile]`. Use the installed two-root export created by packed smoke; the harness expects its `packagedRuntime` source and two selected records. It launches only an owned headless browser/profile, tests source location/comparison reload and native keyboard control, asserts no HTTP/runtime errors, and removes its profile. It does not establish human utility. The [dated browser receipt](release-completion-report.md) records desktop/mobile observations separately from the [human protocol](reader-study-protocol.md).

`view project` returns a schema-1 bounded snapshot of authored knowledge, safe source, explicit source bindings, file API definitions and selected caller/callee relationships. `view export` writes the same snapshot into an offline reader with comparison panes, outline, source line numbers, provenance/freshness labels, local selection links, browser history and keyboard navigation. Both CLI and MCP use the shared operation registry.

The reader retains producer-owned types, authored relationship verbs and existing reviewed freshness; it does not validate execution records or certify inferred prose. Relationships begin collapsed. Body rendering uses text nodes and included-record links, with no active Markdown or remote resources. Styles and scripts are original inline assets bound by SHA-256 content-policy hashes; platform fonts require no external files.

The projection caps records at 40, relationships at 80, each body at 32 KiB and total body text at 256 KiB. Selected implementation bindings precede unrelated navigation. Bodies truncate only at valid UTF-8 boundaries. Input digests, the binding manifest and knowledge graph are rechecked before returning the snapshot. Changed inputs are withheld. Omission/exclusion/truncation counts and partial exit 3 are explicit; none of these checks provides a filesystem-wide transaction.

Selected concepts receive their own knowledge neighbourhood even outside the default ranked set. Structural navigation inspects at most four selected source records (selection, comparison and explicit bound sources), eight definitions per source and one hop per trace. Definition and trace receipts are rechecked alongside the current source index. Only parser-backed high-confidence edges receive `confirmed-static`; agent-reviewed and semantic edges remain `inferred`/`candidate` in this view. A bare unresolved symbol never selects a guessed file. Call scope and unresolved/internal occurrences are shown in the inspector. A definition/source/trace cap keeps coverage partial; relationship omissions include known links whose endpoints were excluded or capped.

Selected call endpoints precede other bound sources during hydration, so a concept with many bindings cannot crowd the comparison's dependency evidence out of the record cap. Selection and comparison always retain first priority.

```text
rke view project --selection docs/knowledge/system.md --comparison src/service.ts --root <repository>
rke view export --selection docs/knowledge/system.md --output .engineering-workflow/cache/reader.html --root <repository>
```

An export receipt returns the output path, byte count, digest and projection revision. Replacing an existing file requires its exact `--expected-digest`; foreign or changed output is refused at preflight. Output must be a separate HTML path, and output reads are bounded. Export locking serializes runtime writers while preserving the ordinary external-filesystem concurrency limitation.

Cached subsystem prose is available with `--include-explanations`. The adapter consumes current validated explanation receipts through their owning runtime API, never by treating cache files as source. It includes at most eight relevant subsystems within the shared 40-record/body caps. Each has a packet-qualified identity, inferred provenance, confidence, source quotes, producer coverage and questions. Its `explains` and typed subsystem links remain inferred candidates. Withheld receipts, omitted subsystems/relationships and incomplete producer coverage keep the projection partial. No receipt is synthesized or promoted during viewing.

Use `--explanation <packet-digest>::<subsystem-id>` with the required source/concept `--selection` to open a specific current subsystem; the selected source/concept becomes the default comparison. Missing, stale or out-of-scope identities are refused. Receipt contents are revalidated before return; changing prose or provenance cannot reuse the previous projection revision. Local Markdown source links prefer included physical records even when an inferred record uses the same source anchor.

For before/after source comparison, pass an explicit `--base <commit-ref>`. The selected path is read from the pinned Git commit and the comparison path (defaulting to selection) from the working tree. `--merge-base` uses the selected commit's merge base with current HEAD. This adapter reads source directly without building an index or creating knowledge-review receipts. Git and working-tree identities are distinct even for the same path; missing sides are labelled as absent. Added, deleted, modified and unchanged states describe source bytes. Different paths are an explicit comparison; only Git-reported rename similarity is labelled a rename candidate, never an established semantic move. Baseline/HEAD, working bytes and rename evidence are rechecked before return.

```text
rke view export --selection src/service.ts --base HEAD --output .engineering-workflow/cache/change-reader.html --root <repository>
rke view project --selection src/old.ts --comparison src/new.ts --base main --merge-base --root <repository>
```

Historical reads accept bounded regular blobs only, reject secrets, binary/oversized content, symlink modes and excluded paths, and do not enable lazy fetch, replacement objects, filesystem monitors, external diffs or text converters. Protected content is refused rather than replaced with an empty side. Source bodies share the 32-KiB cap and partial exit 3. Historical source does not establish historical canonical freshness, execution validation or reachability. Inferred explanation flags require a separate view. This is a side-by-side snapshot, with no line-diff alignment or automatic path pairing.

Source line numbers, section permalink buttons and the outline create snapshot-bound location links. The fragment retains the exact record ID, optional comparison, `anchor=L42` or `anchor=section:<heading-key>`, and the projection `snapshot` revision. Selecting a location in the comparison brings that exact record into the primary pane while retaining its counterpart. Focus and highlighting identify the target; reload and browser history restore it. Duplicate headings receive distinct keys, Unicode headings are supported, and source positions refer only to included body lines. Internal Markdown `#heading-key` and `path#L42` links use the same route; ambiguous physical paths stay inactive. Unknown records/comparisons, malformed locations, changed or unspecified snapshots and missing/capped locations produce visible notices without guessing a target. Document-only bookmarks remain compatible. Each pane retains its own reading position.

The Documents and Evidence buttons collapse their side panes independently without changing selection, bookmarks or reading positions. Pane sizes exposes labelled native range controls for document width (180–320 px), evidence width (220–380 px) and comparison balance (35/65–65/35). Keyboard arrows and pointer input use bounded preset CSS rules; no source-selected inline styles are permitted. Comparison panes stack at narrower widths, and controls disable where their dimension no longer applies. Reset restores visible side panes and default sizes. `/` reveals document navigation before focusing search. Coverage counts sit outside the collapsible navigation and remain rendered. Preferences last for the current page session; reload uses default sizes.

Reader delivery remains short of completed P6. OKF producer/upstream parity and the five-user formative study remain open. Deterministic and browser witnesses are recorded separately in the implementation progress ledger. No full repository graph is required for the reader's useful navigation tasks.

## Selected workspace reading

`workspace view project` and `workspace view export` use the existing workspace authorization, root pins and before/after content snapshots. Supply explicit primary and comparison paths in their owning aliases; a comparison repository requires its comparison path. Without a comparison repository, comparison stays in the primary root. CLI allow-roots and MCP startup allow-roots remain caller configuration, never manifest or tool arguments.

```text
rke workspace view export --manifest workspace.json --selected-repository service --selection docs/knowledge/system.md --comparison-repository client --comparison src/service.ts --root <owner> --allow-root <permitted-root>
```

Records and bookmarks use `alias::local-record-id`; relative Markdown links stay in the originating repository. Search includes aliases and a repository filter narrows document navigation. Every selected root retains its status, input snapshot and omission count in the projection and coverage footer. Roots without an explicit primary/comparison seed are snapshot-checked but contribute no reader records; the filter labels that boundary. No path, symbol or source instruction selects another repository automatically.

The result's `complete` describes reader coverage and agrees with the projection and exit status. `workspaceComplete` separately describes the underlying workspace snapshot/dependency aggregation. Current roots can therefore coexist with a partial reader because of document, relationship or byte caps; a root snapshot never clears those omissions.

Manifest scopes narrow hydration, bindings, traces and inferred receipts. Authored validation requires the complete selected knowledge bundle inside those scopes; pass `--bundle` or `--comparison-bundle` for an explicit alternative. A source-only scope omits unrelated knowledge navigation. Index refresh and producer freshness checks remain repository-owned operations; scopes are query/hydration boundaries, not a filesystem sandbox inside an authorized root. Explanation receipts spanning other scopes are withheld. `--include-explanations` and `--explanation` apply to the primary repository.

Selected primary/comparison records retain first priority; remaining local ranks alternate across contributing roots. The same 40-record, 80-edge and body caps apply to the combined projection. Existing source-bound workspace dependencies appear only between included endpoint files and remain inferred candidates with their declaration kind/resolution; they do not become confirmed runtime edges. Missing endpoints and unresolved mappings keep coverage partial. No name-only relationship is invented.

Reader graph, source, binding and explanation evidence is projected again after aggregation, alongside workspace manifest and source snapshots. Changed roots lose their records and dependent links. A failed primary returns an unavailable result and writes no file; an unavailable comparison root permits a partial primary export with its failure visible. Existing output still requires its exact expected digest, and the workspace manifest cannot be overwritten. Checks are bounded individual observations, without a global filesystem transaction. This surface compares current records across roots; explicit Git-base comparison remains the separate single-root source adapter.


## Fixed-root live reading

Use `view serve` or `workspace view serve` with the same selection arguments as projection. The receipt contains a private loopback URL; keep the CLI or MCP process alive while reading. Refresh snapshot reloads the captured selection and preserves location bookmarks. A changed projection revision makes old bookmarks visibly stale.

The server binds only to 127.0.0.1 on an ephemeral port. Its authenticated GET route accepts no replacement root, path, operation or selection. Sessions capture physical owner/caller roots, selected workspace topology/scopes and request arguments. Physical replacement, retargeting or scope changes require a new session; unavailable or denied children cannot gain authorization on refresh. An explicit single-root Git baseline resolves once at startup. Source evidence is recomputed through the existing producers and caps; refresh creates no canonical knowledge or review receipt.

Keep the URL private because its nonce grants access to the selected evidence. Responses disable caching and remote execution/connections. Invalid request authority is rejected before projection; unavailable evidence returns an opaque failure without serving an older snapshot. Each process supports at most eight sessions, closes idle sessions after ten minutes, and owns their cleanup. MCP input closure drains queued calls before closing its sessions; stopping the owning CLI closes its reader. Offline exports remain independent of a running process.

`rke view serve --selection src/service.ts --root <repository>`

`rke workspace view serve --manifest workspace.json --selected-repository service --selection src/service.ts --root <owner> --allow-root <permitted-root>`


## Code presentation

The reader colors recognized source extensions and explicitly labelled code fences using pinned highlight.js 11.12.0 at export/refresh time. Grammars load only when highlighting is requested. No browser highlighter or remote asset is required. The library's result passes a span/text-only conversion with exact reconstructed-text comparison, then the client creates text nodes and styled spans. Multiline comments/strings retain context; source line numbers and snapshot-bound locations retain their original identities.

Decoration is disposable presentation, not structural or semantic evidence. Unknown/unlabelled languages, failed conversions, oversized token runs and the 64 KiB aggregate decoration cap fall back to plain original code. The original projection, body caps, provenance and content digests remain unchanged. Empty fenced lines remain empty, and source-line placeholders retain their existing layout. Syntax support does not establish parser or language-server qualification.

Mermaid fences now offer on-demand rendering in an opaque script-only sandbox, with exact original source available through a separate control. Invalid syntax, unsupported active content, timeouts and unavailable assets keep plain source. Controls are limited to eight closed fences per export, 8 KiB per fence, 128 library edges and 15 seconds per attempt. Ordinary prose and source records do not load the asset or run the diagram engine. Selection changes remove frames, revoke owned Blob URLs and discard pending messages. The parent accepts only the exact current frame/job and bounded state/height, never SVG, HTML, commands or selection instructions. The pinned Mermaid 11.10.1 asset and complete MIT license are packaged. Parent script hashes and stylesheet hashes/nonces remain enforced; eligible diagram exports permit style attributes for SVG layout while all Markdown remains inert parent content. Runtime integration is implemented; browser fidelity and installed diagram checks remain in progress.

The collapsed relationship inspector separates Incoming → Selected → Outgoing. Each direction initially includes at most four projected links, with explicit counts and four-link expansion steps. Directional rows retain the producer verb, provenance and certainty; candidates are labelled unresolved and have a dashed marker. Self-links appear once under Outgoing. Expansion state and reading position survive selection changes within the snapshot, and keyboard focus stays on the remaining expansion control or the direction heading. Export-wide omissions have unknown direction and remain distinct from links merely hidden in the current panel. This view does not infer endpoints or certify complete dependencies.

The independent OKF producer uses the same four-link directional reveal workflow in its selected relationship panel, adds explicit collapse and retains expansion per document/direction. Its document links keep their producer meaning. That adapter does not import RKE's parser certainty, canonical freshness or inferred-source evidence classes. Producer and compatible upstream have separate normative and browser checks; equivalence of the navigation workflow does not merge their record schemas or generators.

Reader HTML has a separate 12 MiB output/replacement bound to accommodate escaped projection text and the optional pinned renderer. Both first writes and replacements are bounded; existing files still require the exact current digest and a regular unlinked destination. This does not increase projection, source-body or diagram-input budgets. The larger-output regression passed in an isolated build and in the normal distribution build, including wrong-digest refusal without modifying the existing file.

Diagram labels retain authored SVG dimensions and scroll within the opaque frame instead of shrinking to fit a dense or narrow pane. Reduced-motion preferences disable SVG animations/transitions; impossible geometry retains source. These latest rendering refinements require dense/mobile browser qualification.
