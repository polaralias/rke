# Code context and OKF knowledge capabilities

The [architecture](rke-architecture.md) keeps engineering judgement in EWF and deterministic evidence in RKE. This capability pass improves navigation while retaining explicit source and producer boundaries.

## Code navigation

`structure map` reports package-balanced directory clusters, parser/semantic dependency hubs, candidate entry points, edge coverage and token-budgeted links. The token estimate uses UTF-8 bytes divided by four and reports omissions; it is not model-specific tokenization. These are derived landmarks, not architectural conclusions. `structure search` scans bounded candidates before ranking by resolved distinct caller identities and trimming presentation. Incomplete scans are explicit. Package manifests balance retrieval ranks; `context find --source-only` excludes prose from implementation discovery.

`structure impact --base <ref>` selects current and old definitions intersecting changed lines. Deletions remain visible; module-level changes remain visible even in mixed module/function edits. `--merge-base` selects the common ancestor for PR comparisons. Results include a Markdown report and optional recent-author candidates; neither author history nor impact establishes ownership or complete reachability. `path::qualifiedName` seeds prevent traces from following identical names in another file. Static fixtures cover explicit default exports, bounded barrel/re-export chains, TS/JS constructed or annotated receivers, Python modules and class receivers, Java class imports, and local Go module/package boundaries. Dynamic dispatch, reflection, overloads and framework wiring remain limited.

LSP is Language Server Protocol. `structure resolve` selects only an explicitly configured host-owned server profile; CLI/MCP reject raw executables and argument overrides. It requests bounded call hierarchy and stores disposable source/target and repository-input digests. Configuration, indirect dependency or other permitted Git-visible input edits invalidate that evidence. Receipts also bind the resolved executable and declared implementation-input bytes; changes withhold old evidence. Undeclared installed dependencies and environment inputs require re-resolution. Warm reads stat every permitted input but reuse unchanged hashes behind unchanged nanosecond file stat identities, including across CLI invocations; unchanged CLI invocations can reuse a validated disposable stat/hash cache. Fingerprint failure withholds evidence. Tests use a mock server to establish transport, containment and expiry. On 2026-10-07, real Pyright and TypeScript-language-server 6.0.1 with TypeScript 5.9.3 resolved two-file cross-module calls and expired evidence after configuration edits. The latest compiler package without JavaScript tsserver was incompatible with that server. These qualify specific pairings and fixtures, not broad language-server accuracy. No server is downloaded or selected from repository metadata.

## Knowledge support

### Documentation impact during ordinary changes

EWF requires bounded documentation-impact judgement for material code, contract and interface changes. Direct source/document inspection can satisfy it; runtime installation alone requires neither adapter loading nor assessment. Select RKE support when bindings, uncertain document ownership, broader discovery or repository policy make it useful. Existing gates and selected receipt policies still apply. See the [review repair account](../release-completion-report.md).

`documentation assess --base <ref>` combines explicit source/claim bindings with `documentationDiscovery`: bounded lexical Markdown candidates derived from changed path names and enclosing symbols and identifiers in added/removed diff lines. Renames expose both old and new paths; deleted source can still find documentation using old names. New files use bounded current text. Candidate retrieval filters to Markdown before ranking so code matches cannot crowd out documents. Existing ignored/sensitive-path and repository-root boundaries apply; no workflow state or canonical content is authored by assessment.

Discovery reports per-path query terms, document excerpts and related changed paths, with limits of 20 eligible paths, 20 terms per query and 12 returned documents. Oversized input, query reduction and omitted candidates are explicit coverage limitations. Candidates are navigation evidence, not bindings or proof of semantic impact. Empty results do not prove that documentation is unaffected. Inspect owning passages and the existing reading order, including bound documents absent from lexical results; use direct search where coverage is limited.

EWF delivery and host routing require this review for material code changes before completion. The optional post-edit hook returns the same discovery evidence. Ordinary review can finish without a persistent lifecycle or receipt. When receipts are selected, `documentation disposition` requires `--reviewed-document` for returned candidates as well as exact changed-path review. `documentation apply` treats authored `--knowledge` documents as reviewed and requires that flag for additional candidates. An acknowledgement records the agent's review declaration, not machine proof of correctness. Candidate hits do not mandate edits. Receipt validation rechecks candidate coverage, and source drift invalidates the reviewed delta.

Explicit EWF enrichment uses the supported [derived explanation lifecycle](../derived-explanations.md). Bounded source packets include qualified symbol identities, exact initial/crux excerpts and omission counts. The consuming agent authors responsibilities and inferred relationships; prepare/apply/check enforce source, configuration, target/source-set and loaded-runtime identities before reuse. Derived prose is available only with `--include-explanations`, and source-only always excludes it. Check output is compact and budgeted by default. Inferred links do not enter parser/LSP tables or satisfy canonical knowledge verification, and schema/excerpt validity does not establish semantic truth. External/ignored dependency bytes and environment behaviour remain outside the certified input boundary.

Queries naming a concept title exactly receive an explicit exact-title ranking reason; ordinary lexical and relationship evidence retains its limitations.

Native OKF 0.1/0.2 concept support preserves unknown metadata and accepts mapping/list verification events. Generated content time, declared trust and expiry are advisory signals independent of RKE's source-hash review receipts. Relative and bundle-root links resolve deterministically; root index changes invalidate relationship resolution. New generated root indexes declare 0.2 and existing declarations are preserved. OKF format conformance and stricter RKE graph connectivity are separately reported.

`knowledge graph` returns bounded landmarks, directory groups, selected neighbours and omission counts. Explicit non-overlapping `--related-bundle` roots connect knowledge, Tasks and Workstreams through body and structured parent/dependency relationships. Tracker Profiles remain excluded; execution validation stays with OKF Tasks. It does not create a standalone renderer or cross-repository federation. OKF Tasks remains the independent execution ledger, strict validator and visualization producer. Task status is never interpreted as knowledge lifecycle status. Attested Computation metadata is retained as source data and cannot authorize execution.

## Reader projections

`view project`, `view export` and `view serve`, plus their workspace variants, expose bounded reader projections over current source and canonical knowledge. Selected source call neighbours retain qualified paths; unresolved names never select a guessed target file. Canonical freshness, inferred relationships and actual execution evidence remain distinct. Historical Git comparisons show explicit before/after source identities and missing sides without assigning historical canonical freshness.

Offline HTML preserves escaped source, uses bounded syntax decoration and optionally renders Mermaid with the packaged pinned engine in a sandboxed frame. Existing output requires its exact digest before replacement. The process-owned live reader refreshes only captured arguments through an authenticated loopback route, rechecks physical roots and evidence, and closes on idle expiry or transport shutdown. Workspace declarations cannot widen caller authority. These properties are maintained source/test contracts, not independent usability or live-host qualification.

## Host assistance

Repository routing supports Codex, Claude, Gemini, Cursor, Copilot, Windsurf and Kiro. Documented project MCP formats are merged for Claude, Gemini, Cursor and VS Code; other hosts expose explicit activation. Optional Claude post-edit and stateless session/prompt hooks return bounded evidence without writing workflow state, canonical documents or verification receipts. Installed-shim/configuration checks establish the maintained contract; they do not establish live behaviour in every host. Source paths remain contained and errors leave ordinary engineering available.

## Evidence and limits

### Bounded language additions, 2026-10-14

The maintained [language contract](../language-support.md) now includes concrete Go receiver evidence across a regular same-package directory, Swift own-type calls through unconditional same-file extensions, and PHP same-file namespace and flat-trait dispatch. Each confirms only a unique source-qualified declaration. Interfaces, aliases, generics, conflicting/adapted traits, arbitrary receiver inference and dynamic selectors retain uncertainty. Protocol requirements remain declarations rather than concrete dispatch proof. Incoming caller lookup preserves the actual defining type or trait. Repository-map resolution caches by the complete calling-symbol identity so a shadowed caller cannot suppress another method's valid dependency.

[Real gopls qualification](../release-completion-report.md) exercised one local-module cross-file call and configuration invalidation using gopls 0.23.0 and a private Go 1.27.2 toolchain. That evidence is limited to the recorded artifact and project pairing; SDK library sources and all environment/dependency inputs are not attested by the declared implementation digest. It does not establish broad Go compiler or build semantics.

[Eclipse JDT LS qualification](../release-completion-report.md) covers one initialized two-file Java project with classpath expiry. Cold startup changed `.project` and was correctly refused; subsequent resolution used the independently checked initialized project. [clangd qualification](../release-completion-report.md) covers one header/caller project with compilation-database expiry. Neither establishes Android/Kotlin behavior, full SDK/resource attestation or general language correctness.

`tests/context-capabilities.test.ts` exercises changed/deleted symbol selection, duplicate namespaces, static bindings, orientation, OKF metadata/links, focused graphs, host ownership, semantic expiry and post-edit boundaries. Broader parser and transport regressions remain part of `npm test`. These deterministic fixtures establish maintained examples; they are not broad agent-outcome evidence or compiler-grade coverage. The synthetic 102-file benchmark found all ten expected callers with zero unrelated callers. Its latency/output measurements and existing measured agent costs are recorded in [cross-language evidence](../cross-language-evidence.md). Keep commands proportionate to the information needed.

Host profiles are configured outside repository control; see the [profile contract](../../.agents/skills/rke/references/language-server-profiles.md). Output token counts are rough UTF-8 bytes / 4 proxies, not tokenizer measurements or conservative upper bounds.

Stateless pre-push validates explicitly declared OKF roots and RKE bindings, not common directory names. Explicit LSP resolution has a thirty-second protocol budget plus two full workspace fingerprints (up to 512 MiB each); it is a rare escalation and has no thirty-second total wall-clock guarantee. Authorized host profiles do not sandbox server plugins or project configuration.

The [16 October canonical review](../release-completion-report.md) covers this capability contract, its bound source set and current deterministic evidence. Source hashes establish freshness after review; they do not upgrade the historical language-server witnesses or establish controlled agent benefit.
